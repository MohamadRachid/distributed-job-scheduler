WHY THIS EXISTS. scripts/chaos_test.py is the project's centrepiece proof -- the
no-duplicate-accepted-result guarantee, run against the REAL handlers rather than a
re-implementation. It was re-run today for two reasons, and the first is not about
sealing at all.

  1. IT WAS BROKEN, AND HAD BEEN SINCE 2026-09-05. The call to the real `create_job`
     had not been updated when that handler gained a `BackgroundTasks` parameter with
     the checkpoint advisor. The session was landing in that slot and the session
     parameter was left as its Depends sentinel, so the script stopped at step 1. That
     is the price of calling the real handler -- which is also the reason to keep
     calling it -- and it was found today by checking this change against it.

  2. A SEEDED NODE NOW SAYS WHICH AGENT VERSION IT IS. A sealed job is invisible to a
     machine that reads as too old, and a node row with no version reads as too old
     because the guard fails closed. Without this the test would have stopped at step
     2 for a reason that has nothing to do with what it proves.

Both fixes are in the script, dated, with the reason beside them. Nothing about what
the test ASSERTS changed.
